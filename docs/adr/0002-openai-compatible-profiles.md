# 推論先は OpenAI 互換プロファイルで統一し、API キーはブラウザに保持する

翻訳の接続先を、ローカルの `llama.cpp` 固定から、
利用者が登録するプロファイル（表示名、ベース URL、API キー、モデル名、サンプリングパラメータ）へ一般化する。
対象を OpenAI 互換 chat completions を提供する推論先に限定することで、
プロバイダごとのアダプタや種別分岐を持たず、
ローカルの `llama-server` も OpenRouter や OpenAI も単一の手順で扱える。
接続確認も全プロファイル共通の `GET {ベース URL}/models` に統一し、
`llama.cpp` 固有の `/health` 解釈を持たない。

アプリはバックエンドを持たないため、リモート推論先の API キーは
ブラウザの localStorage に保存され、ブラウザから直接送信される。
キーを秘匿するにはプロキシサーバが必要だが、
それは「アプリはプロセスを持たない」（[ADR 0001](0001-external-llamacpp.md)）を覆す
アーキテクチャ変更になる。
単一利用者が自分のマシンで使うローカル Web アプリであり、
キーは利用者自身のものだけを扱うため、
ブラウザ保持のリスクを受容してバックエンドを作らないことを選んだ。
