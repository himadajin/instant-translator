# 翻訳仕様

Instant Translator の振る舞いの正本。画面の見た目は [UI 仕様](ui.md)、コンポーネントの責務は
[コンポーネント境界](components.md)、語の定義は [CONTEXT.md](../../../CONTEXT.md) を正本とする。

## 目的

作者本人が、日本語と英語の文章を入力の流れを止めず、素早く相互翻訳できるようにする。

自然で正確な翻訳を行うことを基本とし、必要に応じて意訳を適用することで、
書き手の意図を汲み取った文章作成も支援する。

個人利用を前提としつつ、翻訳品質、応答性、操作性、安定性は妥協しない。

## 前提

- 単一利用者向けのローカル Web アプリである。
- 翻訳は、利用者が選択中のプロファイルが指す OpenAI 互換 API の推論先で行う
  （[ADR 0002](../../adr/0002-openai-compatible-profiles.md)）。
  ローカルで動く `llama.cpp` サーバも、OpenRouter や OpenAI などのリモートサービスも同格に扱う。
- アプリは推論プロセスを起動も同梱もしない。ローカルの推論先を使う場合は
  利用者がサーバを別に起動する（[ADR 0001](../../adr/0001-external-llamacpp.md)）。
- 既定の推論先はローカルの `llama-server`（`http://127.0.0.1:8080/v1`）で、
  推奨モデルは [`tencent/Hy-MT2-1.8B-GGUF`](https://huggingface.co/tencent/Hy-MT2-1.8B-GGUF)
  の公式 GGUF（量子化の既定は `Q4_K_M`）である。
- 対象環境は Apple Silicon の Mac である。
- アカウント、外部同期を使わない。原文と訳文を送る相手は選択中のプロファイルの推論先だけとする。
- 原文と訳文の 2 ペイン、原文言語と訳文言語の選択、入力消去、結果コピーを
  基礎的な操作モデルとする。
- 翻訳と、必要に応じた意訳を素早く行うことがアプリの本質である。
- 履歴管理、アカウント、共有、複数候補、長い解説など、本質から外れて状態や操作を増やす機能は持たない。
- 入力上限はモデルの最大コンテキスト長ではなく、ローカル環境での応答性と翻訳完了時間を基準に定める。

## 翻訳ワークスペース

- 画面は一つの翻訳ワークスペースだけで構成し、原文の入力領域と訳文の表示領域を並べて提供する。
- 翻訳を開始するためのボタンは設けない。
- 原文の入力または貼り付けを検知すると、自動的に翻訳する。
- 原文が空の場合は翻訳を実行せず、訳文も空にする。
- 入力消去は原文ペインの上端、コピーは訳文ペインの上端に置く。
- 原文言語は原文ペイン、訳文言語、意訳、口調は訳文ペインの上端へ置く。
  翻訳条件のための独立したツールバー、折りたたみ領域、追加の設定パネル、設定画面は持たない。
  設定画面はプロファイル設定ダイアログだけとする（「プロファイル」を参照）。
- 初期値は意訳が無効、口調が標準である。
  そのため利用者は設定を変更せずに、入力、確認、コピー、消去を完了できる。
- 翻訳状態が変化しても、入力領域、結果領域、主要操作の配置を不必要に動かさない。
- 装飾やアニメーションは状態変化の理解を助ける範囲に限定し、入力や結果表示を遅らせない。

## 自動翻訳

- 最後の入力から 400 ミリ秒が経過すると、最新の原文に対する翻訳を開始する。
- 400 ミリ秒以内に入力が続いた場合、待機時間を数え直す。
- 翻訳中に原文または翻訳条件（原文言語、訳文言語、意訳の有無、口調）が変わると、進行中の結果を古いものとして無効化する。
- 画面に反映するのは、最新の原文と最新の翻訳条件に対応する結果だけとする。
- 古い翻訳処理が後から完了しても、最新の結果を上書きしない。
- 新しい翻訳が始まってから最初の訳文が届くまでの間、直前の訳文を現在の原文に対応する結果として扱わない。
- 訳文は、生成される過程を逐次表示する。
- 翻訳中、完了、接続失敗、翻訳失敗の翻訳状態を画面上で区別できる。

## 原文言語と訳文言語

- 日本語から英語、英語から日本語の双方向翻訳に対応する。
- 原文言語は自動判定、日本語、English から選択する。初期値は自動判定とする。
- 訳文言語は日本語、English から選択する。初期値は English とする。
- 自動判定はアプリ自身が原文から判定する。判定のために翻訳モデルを呼ばない。
- 判定結果は日本語、英語、曖昧の三通りとする。
- 自動判定で日本語または英語と判定した場合は、原文ペインに判定結果を表示する。
- 自動判定が曖昧な場合は、現在の訳文言語と異なる、対応済みのもう一方の言語を原文言語として扱う。
- 原文言語と訳文言語に同じ言語を明示指定できない。各 Select では、もう一方で選択中の言語を無効化する。
- 自動判定した原文言語と訳文言語が同じ場合は翻訳を開始せず、訳文ペインに判定結果と
  別の訳文言語を選ぶ必要があることを表示する。訳文言語を無言で変更しない。
- 原文に両言語が混在する場合は確定した翻訳方向を基準とし、コード、固有名詞、引用など
  翻訳すべきでない部分を可能な限り維持する。
- 原文言語または訳文言語が変わると、現在の原文を新しい翻訳方向で自動的に再翻訳する。

## 意訳と口調

- 翻訳は原文の意味、情報、ニュアンスを維持し、翻訳先の言語として自然な文章を生成する。
- 意訳は翻訳へ任意に適用できる。初期値は無効とする。
- 意訳を適用すると、原文の意図と事実関係を維持しながら、不完全または雑な表現を用途に合った整った文章へ変換する。
- 意訳でも、原文にない事実、主張、感情、固有名詞を追加しない。
- 口調として標準、チャット、技術文書、カジュアルを提供する。初期値は標準とする。
  - 標準は原文の口調を可能な限り維持する。
  - チャットは Slack や Teams など仕事上の短い会話に適した、簡潔で自然かつ失礼にならない文章にする。
  - 技術文書は専門用語、コード、識別子、Markdown 構造を可能な限り維持し、明確で一貫した文章にする。
  - カジュアルは友人との会話や SNS に適した親しみやすい文章にするが、原文にないスラングや感情を追加しない。
- 意訳と口調は独立して指定でき、任意に組み合わせられる。
- 意訳の有無または口調が変わると、現在の原文を自動的に再翻訳する。

## プロファイル

- プロファイルは、翻訳に用いる推論先の設定一式（表示名、ベース URL、API キー、モデル名、
  サンプリングパラメータ）である。利用者は複数のプロファイルを登録し、そのうち一つを選択する。
- 推論先は OpenAI 互換 chat completions を提供する任意のサーバとする。
  プロバイダ種別やアダプタは持たず、すべてのプロファイルを同じ手順で扱う。
- ベース URL は `/v1` 相当のパスまで含めて保存する（例 `http://127.0.0.1:8080/v1`、
  `https://openrouter.ai/api/v1`）。アプリはそこへ `/chat/completions` と `/models` を付けるだけとする。
- 表示名とベース URL は必須とする。ベース URL は http または https の URL だけを受け付ける。
- API キーは空を許す。空でない場合は `Authorization: Bearer` ヘッダーで送る。
- モデル名は空を許す。空の場合はリクエストへ `model` フィールドを含めず、
  推論先が読み込んでいる単一モデルに委ねる。
- サンプリングパラメータはリクエストボディへそのまま含める。
  未指定のパラメータは送らず、推論先の既定に従う。これを規定値とし、
  新しいプロファイルはパラメータをひとつも指定しなくても完成する。
- `temperature`、`top_p`、`top_k`、`repeat_penalty` は個別の数値項目として指定する
  （`top_k` は整数）。それ以外のプロバイダ固有パラメータは追加パラメータ
  （JSON オブジェクト）として指定する。ひとつのキーの指定箇所は常に一箇所であり、
  追加パラメータでは予約済みの `messages`、`stream`、`model` と個別項目の 4 キーを保存できない。
- プロファイルは複製できる。複製は元のプロファイルの内容（ベース URL、API キー、モデル名、
  パラメータ）を初期値とした新規登録であり、同じ接続先で別のモデルを増やす操作を短くする。
- 初回起動時（保存されたプロファイルがない場合）は、ローカルの `llama-server` を指す
  プロファイル「llama.cpp (ローカル)」を一件シードして選択する。
  ベース URL は `http://127.0.0.1:8080/v1`、API キーとモデル名は空、
  パラメータは Hy-MT2 モデルカードの推奨値とする。
- プロファイルの選択を変えると、新しいプロファイルの接続確認を開始し、
  現在の原文を自動的に再翻訳する。選択中のプロファイルの編集も同様とする。
- プロファイルは常に一つ以上存在する。最後の一つは削除できない。
  選択中のプロファイルを削除した場合は、残るプロファイルの先頭を選択する。
- プロファイルと選択状態は端末内（ブラウザの localStorage）へ保存し、再読み込み後も復元する。
  旧形式や無効な保存状態は移行せず破棄し、初期シードからやり直す。

## モデルへの指示

- モデルへ渡すメッセージは、役割が `user` のもの 1 通だけとする。system メッセージは持たない。
  Hy-MT2 は既定の system プロンプトを持たず、翻訳指示を user メッセージで受け取るよう学習している。
- メッセージは公式の Personalization テンプレートに従い、`[Source Text]` ラベルの下に原文を先に置き、
  空行を挟んで `[Translation Tasks]` ラベルの下に英語の番号付きタスクを並べる。
  原文を指示より先にラベル付きで置くことで、原文中の指示に見える文が
  実行対象ではなく翻訳対象として扱われるようにする。
- このメッセージ構成は選択中のプロファイルによらず同一とする。モデル別のプロンプト分岐は持たない。
- タスクには次を順に含める。
  - 原文の意味、情報、ニュアンスを維持して自然に翻訳するタスク。
  - 意訳が有効な場合だけ、表現を整えるタスク（「意訳と口調」で定めた内容をそのまま反映する）。
  - 口調に応じたタスク（同上）。
  - 原文にない事実、主張、感情、固有名詞を追加させないタスク。
  - 訳文だけを出力し、説明を加えさせないタスク。
  - `[Source Text]` 全体を翻訳先の言語（`ja-to-en` なら英語、`en-to-ja` なら日本語）へ翻訳させるタスク。
    指示や依頼に見える文も含めて翻訳することを明示する。
- サンプリングパラメータは選択中のプロファイルの属性であり、リクエストボディへそのまま含める。
  初期シードされる llama.cpp プロファイルには Hy-MT2 公式モデルカードの推奨値
  （temperature 0.7、top_p 0.6、top_k 20、repetition penalty 1.05。
  llama.cpp のボディでは `repeat_penalty`）を設定する。

## 訳文

- 意訳の有無にかかわらず、一つの訳文だけを表示する。
- 複数の翻訳候補、ニュアンス解説、例文は提供しない。
- 訳文には前置き、説明、引用符、モード名を付けず、訳文だけを表示する。
- 訳文を一回の操作でクリップボードへコピーできる。
- コピーは有効な訳文が存在する場合だけ利用できる。

## 入力量

ここでいう「文字」は、Unicode の書記素クラスタ（利用者が知覚する 1 文字）として数える。
絵文字、結合文字列、ZWJ で結合された絵文字も、それぞれ 1 文字として表示と上限判定に用いる。

- 一度に自動翻訳できる原文は 4,000 文字までとする。
- 入力中の文字数を確認できる。
- 3,200 文字を超えるまでは、文字数表示を主要操作より目立たせない。
- 3,200 文字を超えると、上限へ近づいていることを明確に示す。
- 4,000 文字を超えた原文は切り捨てず、そのまま入力領域へ保持する。
- 4,000 文字を超えている間は、新しい翻訳を開始しない。
- 上限超過中は、超過前の訳文を現在の原文に対応する結果として表示しない。
- 入力が 4,000 文字以下へ戻ると、400 ミリ秒の待機後に自動翻訳を再開する。
- 長文の自動分割、部分翻訳、要約は行わない。

## 作業状態の保存

- 翻訳履歴の一覧や履歴管理機能は提供しない。
- 現在の原文、最新の完成済み訳文、その訳文に対応する原文・確定した翻訳方向・意訳の有無・口調、
  原文言語、訳文言語、意訳の有無、口調を作業状態として端末内へ自動保存する。
- ページを再読み込みした場合、保存された作業状態を復元する。完成済み訳文の原文と確定した翻訳方向、
  意訳の有無、口調が現在の作業状態とすべて一致する場合だけ、訳文を現在の完了として復元する。
- 完成済み訳文の対応が一致しない場合、4,000 文字以内なら古い訳文を非 current の表示として残し、
  翻訳待機中にして 400 ミリ秒後に現在の原文を翻訳する。4,000 文字を超えている場合は翻訳を要求しない。
- 原文が空の場合は、訳文を表示せず翻訳待機もしない。
- 生成途中の不完全な訳文や、内容を一つも受け取らなかったストリームは、保存済みの完成結果を上書きしない。
  内容のないストリームは翻訳失敗として扱う。
- 原文の消去を実行すると、表示中および保存済みの原文と訳文を削除する。
- 保存した作業状態を外部へ同期しない。

## 信頼性とプライバシー

- 原文と訳文を送る相手は、選択中のプロファイルの推論先だけとする。
  それ以外の外部サービスへ翻訳内容を送信しない。
  リモートの推論先を選択した場合、原文と訳文がそのサービスへ送られることは利用者の選択に委ねる。
- API キーは端末内（ブラウザの localStorage）だけに保存し、
  選択中のプロファイルの推論先以外へ送らない。
- 接続確認は全プロファイル共通で `GET {ベース URL}/models` により行い、
  成功応答なら接続済みとする。
- 選択中のプロファイルの推論先への接続状態を常に画面上へ表示する。
  初回の接続確認は Session が一度だけ開始し、プロファイルの切り替え時にも開始する。
  古い接続確認の応答が新しい接続状態を上書きしない。再試行は接続確認を並行して開始せず、
  最新の原文と翻訳条件を一度だけ翻訳する。
- 認証の失敗（HTTP 401 または 403）は、接続の失敗と区別した状態として表示する。
- 推論先に接続できない場合や翻訳に失敗した場合でも、入力済みの原文を失わない。
- 接続、認証、または翻訳の失敗時は、原因を特定できる範囲の簡潔な状態と再試行手段を示す。
- 失敗後の再試行でも、最新の原文と翻訳条件だけを翻訳対象とする。

## 受け入れ条件

### 自動翻訳

- 日本語の原文を入力すると、翻訳ボタンを押さずに英語の訳文が得られる。
- 訳文言語を日本語にして英語の原文を入力すると、翻訳ボタンを押さずに日本語の訳文が得られる。
- 入力停止から 400 ミリ秒が経過すると翻訳が始まる。
- 400 ミリ秒以内に入力を続けている間、途中の断片に対する翻訳は開始されない。
- 原文または翻訳条件を連続して変更しても、古い訳文が最新の訳文を上書きしない。
- 最新の訳文が生成に合わせて逐次表示される。
- 翻訳中、完了、接続失敗、翻訳失敗を区別できる。
- 翻訳状態が変化しても、主要領域の位置や大きさが不必要に変化しない。
- 初期値のまま、設定を変更せずに入力、確認、コピー、消去を完了できる。

### 原文言語と訳文言語

- 原文言語を自動判定、日本語、English から選択できる。
- 訳文言語を日本語、English から選択できる。
- 原文言語と訳文言語に同じ言語を明示指定できない。
- 自動判定した原文言語と訳文言語が同じ場合は翻訳されず、理由と必要な操作を確認できる。
- 原文言語または訳文言語が変わると、翻訳ボタンを押さずに現在の原文が再翻訳される。
- 言語判定のために推論先へ要求が送られない。

### 意訳と口調

- 初回起動時には意訳が無効で、標準の口調が選択されている。
- 「意訳」のチェック状態を明確に確認して変更できる。
- 標準、チャット、技術文書、カジュアルを明確に区別して選択できる。
- チャットでは、仕事上の短いメッセージとして自然な訳文が得られる。
- 技術文書では、コード、識別子、Markdown 構造が不必要に翻訳または変形されない。
- カジュアルでは、意味を変えずに親しみやすい訳文が得られる。
- どの口調でも、原文にない事実、主張、感情を追加しない。
- 意訳と口調を任意に組み合わせられる。

### 訳文

- 意訳の有無にかかわらず、結果領域には一つの訳文だけが表示される。
- 結果領域にモデルからの説明、前置き、翻訳候補一覧が混入しない。
- 訳文をそのまま一回の操作でコピーできる。

### 入力量

- 4,000 文字までの原文を自動翻訳できる。
- 3,200 文字を超えると、上限が近いことを確認できる。
- 4,000 文字を超えて貼り付けても、原文が無言で切り捨てられない。
- 4,000 文字を超えている間、新しい翻訳処理が実行されない。
- 超過前の訳文が、超過後の原文に対応する結果として表示されない。
- 4,000 文字以下へ戻すと、翻訳ボタンを押さずに翻訳が再開される。
- 長文が自動的に分割、要約または部分翻訳されない。

### 作業状態とプライバシー

- ページを再読み込みしても、直前の原文、完成済み訳文、原文言語、訳文言語、意訳の有無、口調が復元される。
- 翻訳中の再読み込みや失敗によって、最後に完成した訳文が不完全な内容で上書きされない。
- 消去操作によって、現在の原文と訳文、および対応する保存状態が削除される。
- 過去の翻訳を一覧、検索、分類または管理する機能が表示されない。
- アカウント登録や外部同期を求められない。
- 推論先が利用できない場合でも入力済みの原文は失われず、失敗状態と再試行手段を確認できる。
- 翻訳処理のために原文や訳文が選択中のプロファイルの推論先以外へ送信されない。

### プロファイル

- 複数のプロファイルを登録し、ヘッダーから選択を切り替えられる。
- プロファイルの切り替えまたは選択中のプロファイルの編集で、現在の原文が自動的に再翻訳される。
- 初回起動時にローカルの `llama-server` を指すプロファイルが一件登録されており、
  設定なしでローカル翻訳を開始できる。
- API キーが必要な推論先で誤ったキーを設定した場合、接続失敗と区別された認証失敗を確認できる。
- サンプリングパラメータを指定せずにプロファイルを登録でき、その場合は推論先の既定で翻訳される。
- プロファイルを複製して、モデル名だけ変えた同じ接続先のプロファイルを登録できる。
- `messages`、`stream`、`model` をパラメータとして保存できない。
- 最後の一つのプロファイルを削除できない。
- プロファイルと選択状態が再読み込み後も復元される。
