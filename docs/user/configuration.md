# 設定

翻訳の接続先は「プロファイル」として画面から設定する。
ヘッダー右上の歯車アイコンでプロファイル設定ダイアログを開き、
プロファイルの追加、編集、複製、削除ができる。
使うプロファイルはヘッダーのプルダウンで切り替える。

## プロファイル

プロファイルは次の項目を持つ。

| 項目                   | 内容                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| 表示名                 | ヘッダーのプルダウンに出る名前。必須。                               |
| ベース URL             | OpenAI 互換 API のベース URL。`/v1` まで含めて書く。必須。           |
| API キー               | 認証が必要な推論先のキー。不要なら空にする。                         |
| モデル名               | リクエストの `model` に入る値。空にすると `model` を送らない。       |
| サンプリングパラメータ | `temperature`、`top_p`、`top_k`、`repeat_penalty` の数値フィールド。 |
| 追加パラメータ         | 上記以外に推論先へ渡す任意のフィールドの JSON オブジェクト。         |

接続先は OpenAI 互換の chat completions API（`POST {ベース URL}/chat/completions`）を
提供していれば何でもよい。接続確認には `GET {ベース URL}/models` を使う。

ベース URL の例:

- ローカルの `llama-server`: `http://127.0.0.1:8080/v1`
- OpenRouter: `https://openrouter.ai/api/v1`
- OpenAI: `https://api.openai.com/v1`

パラメータはすべて空のままでよい。
空欄のパラメータは送信されず、推論先の既定で翻訳される。
値を入れたパラメータだけがリクエストボディへそのまま含まれる。
追加パラメータには推論先が受け付ける任意のフィールド
（OpenRouter の `provider` 指定など）を書ける。
`messages`、`stream`、`model` はアプリが管理するため指定できず、
サンプリングパラメータの 4 キーは数値フィールド側で指定する。

同じ接続先で別のモデルを使うプロファイルを増やすときは、
既存プロファイルの複製ボタンを押す。
ベース URL、API キー、パラメータを引き継いだ追加フォームが開くので、
モデル名と表示名を変えて保存する。

プロファイルと選択状態はブラウザの localStorage に保存される。
API キーもブラウザ内だけに保存され、選択中のプロファイルの推論先以外へは送られない。

## 既定のプロファイル

初回起動時には「llama.cpp (ローカル)」プロファイルが一件登録されている。

- ベース URL: `http://127.0.0.1:8080/v1`（`llama-server` の既定と同じ）
- API キー、モデル名: 空
- パラメータ: Hy-MT2 モデルカードの推奨値
  （`temperature 0.7`、`top_p 0.6`、`top_k 20`、`repeat_penalty 1.05`）

`llama-server` を別のポートで起動する場合は、
このプロファイルのベース URL を同じポートへ書き換える。

```sh
llama-server --port 8081 -hf tencent/Hy-MT2-1.8B-GGUF:Q4_K_M
```

`llama.cpp` の既定設定はローカル Web アプリから利用できるため、この用途で追加の CORS オプションを
指定する必要はない。

## リモートの推論先を使う

OpenRouter や OpenAI を使うには、プロファイルを追加して
ベース URL、API キー、モデル名を設定する。
原文と訳文はそのサービスへ送信されることに注意する。

キーが誤っている場合は、接続状態が「認証エラー」になり、
訳文ペインにも認証の失敗が表示される。

## 量子化を選ぶ

ローカルの `llama-server` で使う量子化の既定は 4-bit 相当の `Q4_K_M` である。
`-hf` の `:` 以降で量子化を指定する。
指定を省いた場合も `Q4_K_M` が選ばれるが、既定で使うときも `:Q4_K_M` を明示する。

[モデルのリポジトリ](https://huggingface.co/tencent/Hy-MT2-1.8B-GGUF)には
`Q4_K_M`（約 1.1 GB）、`Q6_K`（約 1.5 GB）、`Q8_0`（約 1.9 GB）がある。
量子化を重くするとメモリ使用量は増えるが、翻訳品質は上がる。
より軽い量子化は
[`tencent/Hy-MT2-1.8B-2Bit-GGUF`](https://huggingface.co/tencent/Hy-MT2-1.8B-2Bit-GGUF)
など別のリポジトリで公開されている。

ダウンロード済みのモデルファイルを直接指定することもできる。

```sh
llama-server -m /path/to/Hy-MT2-1.8B-Q4_K_M.gguf
```

`-hf` で取得したモデルの保存先は、環境変数 `LLAMA_CACHE` で変えられる。

## その他の起動オプション

`llama-server` のオプション一覧は次で確認できる。

```sh
llama-server --help
```
